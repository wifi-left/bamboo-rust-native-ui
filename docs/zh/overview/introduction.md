# 简介

> Bamboo Native UI 是面向原生 Windows 桌面应用的 UI 框架，小巧、声明式、保留模式，使用 GDI 在脏矩形上绘制。

## 它是什么

Bamboo Native UI（`bamboo-native-ui`）是 Rust 库，打开一个原生 Win32 窗口，保存一棵保留控件树，把它们绘制到持久后台缓冲中。应用拥有布局：它给每个控件分配矩形，通常是在窗口尺寸改变时。框架拥有像素：它合并受损区域，只绘制与这些区域相交的控件，再把这些部分 blit 到屏幕。

它不是一个通用工具包。没有 WebView，也没有即时模式的重绘循环。默认渲染器是 GDI；可以选择 Direct2D 硬件或软件渲染器，但二者都不是必需的。窗口系统未做跨平台抽象：所有触及 Win32 的部分都位于一个宿主边界之后，而应用和控件日常使用的类型（`Rect`、`Size`、`Color`、`Event`、`Palette`、`Canvas`）是平台中立的。

## 它为何存在

即时模式库在每一帧都重新布局并重绘整个窗口。对工具和原型来说，这是不错的默认选择，但音乐播放器大部分时间处于空闲状态：一个静态页面、一首正在播放的曲目、一条缓慢变化的进度条。为了显示同样的画面每秒重绘窗口六十次，既浪费电能，也是低端机器上卡顿的来源。

Bamboo Native UI 持有相反的契约：

- 应用计算控件矩形；框架只绘制脏矩形并分发规范化后的事件。
- 每个窗口一个持久后台缓冲；只 blit 脏边界框。
- 空闲即零绘制。没有显式定时器就不会有任何周期性重绘。
- 禁止在绘制路径上分配内存；画刷、字体和转换后的图像在窗口生命周期内缓存。

结果是，框架的开销与发生变化的部分成正比。悬停改变两个小控件，只耗费两次小重绘，而不是一帧。

## 当前状态

- **里程碑 M2 至 M4 已完成。** M2、M2.5 和 M2.6 这几轮构建了控件库（包括按控件的间隙处理阶段）、按实例属性和触发器，以及容器拥有的重叠与命中测试。M3 添加了 UI 自动化，包括闭合字段文本模型。M4 添加了原生表面：工具提示、上下文菜单、对话框、托盘图标和全局热键。只剩分层窗口表面尚未完成。
- **M6.5 进行中。** 文本与内容组已完成（自动换行标签、图标、徽标、分隔线、头像、快捷键芯片、可复制文本、跑马灯、带内联链接的富文本）。输入控件、反馈控件和窗口内模态外壳已就位。框架绘制的文本编辑器（`.painted()`）内联渲染输入法组字，没有原生子控件也能暴露实时的 UI 自动化文本。
- **M7 已实现。** 布局皮肤可以用 `.buixml` 编写，并在运行时消费（`feature = "layout-xml"`）或编译进 Rust（`feature = "layout-compiled"`）。M7.8 添加了 `.buitheme` 主题文档（`feature = "theme-xml"`），它们映射到 `Palette`。

`crates/showcase` 中的全控件演示是上述每一特性的参考接线。

## 它面向谁

- 构建 **Windows 桌面应用**、希望获得原生控件、原生文本渲染和可预测 CPU 占用的 Rust 开发者。
- 拥有**大部分静态页面**、只有少量动画或交互区域的应用，例如媒体播放器、仪表盘和设备工具。
- 希望**自己掌控布局算术**而不是交给约束求解器、并且愿意在尺寸改变时分配矩形的项目。
- 需要 **UI 自动化**、输入法、剪贴板和原生菜单，又不想引入完整 GUI 工具包的团队。

如果你需要跨平台窗口、浏览器渲染模型、庞大的第三方主题生态，或在整个窗口上自由地逐帧动画，那么它并不合适。
